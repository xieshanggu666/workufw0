# 🏠 智居 · 智能家居场景联动与设备健康看板

基于 **Vue 3 + Vite + Pinia（前端）+ Express + SQLite（后端）** 的智能家居演示看板。纯 mock 设备数据，无真实硬件接入。

## 技术栈

- 前端：Vue 3 + Vite + Pinia
- 后端：Node.js 内置 `node:sqlite` + Express，REST API
- 数据库：`server/home.db`（SQLite，首次启动自动建表 + 预置演示数据）

## 运行

```bash
npm install
npm run dev
```

前端 http://localhost:5190（Vite 已代理 `/api` 到 http://localhost:4120）。
需 Node ≥ 22.13。

## 功能

- **家庭共享（邀请 · 角色权限 · 按房间/设备细粒度授权 · 撤销回收）**：户主/家庭管理员/家庭成员/访客四级角色，授权范围贯穿**设备控制、场景执行、场景管理、定额告警处理、定额配置、成员管理、工单分派、工单处理**八项；角色默认权限之外可逐项追加自定义授权，还可把成员/访客的操作**按房间、按单设备限定范围**（scope 为空=全屋不限）。邀请码 7 天有效（待接受→已接受/已取消/已过期，可续期重发），邀请、续邀、接受、编辑权限/范围、撤销/恢复**全程携带范围快照、同一令牌即时生效**；访客凭码加入即获令牌；撤销成员令牌立即失效、全部授权当场收回，可「恢复」直接回到在组（范围保留）或「重新邀请」走邀请码流程复用原身份，形成**可回收协作闭环**。所有成员/访客操作（设备开关、场景触发、告警处理等）与家庭管理事件均带**操作人+角色**记入家庭日志时间线，越权操作同样留痕，支持按设备/场景/定额/家庭协作分类及按操作人筛选
- **细粒度授权统一校验与换房迁移**：设备开关/编辑/增删/换房、场景编排/触发、定额配置/批量、告警处理/批量、工单分派与处理全部在功能权限守卫之后再做**资源范围校验**（服务端最终裁决，前端按 `/api/state` 下发的 `in_scope` 标记置灰）；场景执行前对全部已绑定动作设备统一预检，**任一设备越范围则整单 403**（不允许借场景越权联动部分设备）。范围按 `devices.room_id`（房间授权，动态）与稳定 `device_id`（设备授权）判定——**设备换房时房间授权随设备自动迁入/迁出、设备授权按标识不丢失**，历史授权无需数据搬迁；换房的目标房间也必须在操作者范围内。设备删除后其设备定额/工单仅全屋不限或仍显式持有该 device_id 者可处理，成员范围中残留的已删除设备在名册标记，重新保存即清理
- **健康看板**：设备在线/异常统计、房间分布、设备类型、告警中心（低电量/信号弱/离线/能耗尖峰/定额超标）、全屋 24h 能耗趋势、定额执行情况
- **设备管理**：按房间/类型/状态筛选，添加/删除设备，开关切换，功率编辑、电量/信号条（操作按当前身份权限置灰，后端二次强制校验）
- **场景联动**：可视化动作编排（设备→动作），创建/启用停用/触发场景，触发后写入日志并联动开关真实设备状态（访客默认仅可触发场景）
- **能耗统计**：按设备开关/功率变化分段累计用电（功率×时长），近24小时总量、按房间分布、设备用电排行、实时功率、节能提示；已删除设备历史保留并标记；页面底部联动展示周期定额用量
- **能耗定额与超标预警闭环**：按房间/设备配置日、周（周一起）、月额度；持续聚合「已结分段 + 运行中设备实时折算」用量；80% 预警、100% 超标，同一额度同一周期只通知一次且可由预警升级为超标；调整额度/周期后告警身份、阈值、状态立即校准（上调误报自动解除、下调再越线自动重开重报）；告警保留 待处理→处理中→已处理/已忽略 状态机与处理备注（家庭成员及以上可处理，配置管理需管理员）；额度新建/调整/停用/删除全程留痕；跨周期自动结转、额度停用/删除自动解除；看板告警与能耗统计联动，新告警/升级/重开 toast 通知（同一身份不重复弹）
- **批量定额策略与告警批量处理**：定额配置支持跨房间/设备批量新建（同一周期+额度一次应用到多个对象，已存在同周期定额的对象自动置灰跳过）与批量调整/启停/删除（勾选多条定额统一应用）；整批在**单事务**内落库、末尾统一评估一次——历史告警随周期/额度调整整体迁移（旧周期结存、当前周期按新阈值校准）、实时用量一次重算，逐项评估的中间态不会触发错报；每个对象独立校验、独立写留痕（含对象快照，额度删除后审计仍可归属），单项冲突（重复定额、周期撞车、对象不存在）只跳过该项并逐项反馈成败。告警处理同样支持勾选多条统一流转+统一备注，逐条复用状态机校验，每条成功项单独写家庭日志时间线，形成逐项审计
- **家庭日志时间线**：设备、场景、定额预警/超标、家庭协作（邀请/接受/撤销/恢复/权限调整）、告警工单（自动生成/分派/接单/挂起/完成/复开）统一时间线，按类别与操作人过滤
- **告警工单闭环（离线 · 低电量 · 信号弱 · 能耗超标）**：四类告警每 30s 自动生成工单（离线/低电量&信号弱按设备、超标按具体定额告警；同一告警身份仅一张未完成工单，部分唯一索引兜底），工单号 `WO-日期-序号`；状态机 `待分派→已分派→已接单→处理中 ⇄ 已挂起→已完成`，完成后可**复开**（必须重新分派才能继续）；支持分派/改派（管理权限）、接单后动作强制处理人本人、挂起/完成/复开必填原因，完整处理时间线（操作人+角色+状态流转）可在工单详情查看；源告警消除不自动关单只标记「源已消除·待核实」，同一问题持续不重复开单，已完成单需经历「消除→复发」才另开新单、未消除可直接复开；设备删除/成员撤销工单快照保留；看板告警中心、定额告警均可点击直达工单，新工单 toast 通知，Tab 角标显示未完成数

## 分段用电模型

- `energy_segments`：每台开启运行中设备的段首（设备标识 + 名称/房间/功率快照 + 起始时间）。开关切换、功率编辑、改名、换房时旧段立即结落，再按当前状态开新段
- `energy_records`：结落的分段明细，按 `device_id` 稳定归属（删除设备不级联），含完整 ISO 起止时间、产生时的名称/房间快照与 kWh；**结段/重启补结时跨本地整点自动拆行**（日、周、月边界都是整点，一并覆盖），每行只归属一个小时与一个自然日；服务端每 30s 模拟运行节拍结段续开，**明细保留 7 天**
- `energy_daily_room` / `energy_daily_device`：按「自然日（本地零点 ISO）× 房间快照 / 设备标识」固化的已结用量，明细插入的唯一入口同步累计、不随 7 天明细清理删除；月/周周期累计中「已完成自然日」一律读日表，因此旧明细被清理后周期用量不回落、超标告警不被误解除；旧库首次启动自动从现存明细按自然日分摊回填一次（兼容旧版未拆长段、watts=0 迁移行）
- 旧版 `energy(device_name,room,kwh,hour)` 数据首次启动自动迁移：名称唯一命中的绑定设备标识，重名/设备已删除的不猜绑，保留名称房间快照（排行中标记「旧记录」）
- 看板 24h 趋势、能耗排行与尖峰告警均读自分段记录；前端 20s 自动刷新

## 统一区间分摊（`server/prorate.js`）

跨「小时 / 自然日 / 周 / 月」边界的运行段绝不按结束时间整段归属，而是按 功率×重叠时长 拆分，三处记账共用同一口径：

- **分段结算**：结段（开关/改名/换房/改功率/30s 节拍）与重启补结时，跨本地整点的段自动拆成多行，拆点恰为整点、无重叠无空隙，每行携带各自的 kWh
- **小时趋势**：24h 聚合按「与窗口、与小时桶的重叠时长」分摊，24 个小时桶对齐窗口起点连续铺满，桶和严格等于窗口总量；取数改为与窗口相交（`start_time < 窗口终点`），跨窗口段只计落入部分
- **定额统计**：周期用量 = 「已完成自然日」的日固化用量（`energy_daily_*`，明细 7 天清理不影响）+ 当前日按「与周期窗口的重叠时长」聚合已结段 + 周期起点之后的未结段实时折算（仍受重启 1h 上限）；跨周期运行段不再被整段计入新周期，消除跨零点/跨周一/跨月初一过边界就虚高超标误报；月/周周期长于明细保留期，用量不再随历史明细清理而减少、超标告警不再因此被误解除
- **日用量固化与历史回填**：每条已结段插入时即按自然日累计进日固化表（跨午夜段拆日）；旧版库首次启动检测到日表为空时，用现存明细按完整起止时间一次性分摊回填，历史库中旧版未拆的长段、watts=0 的旧迁移行无需改写即正确归属，回填仅执行一次（幂等，不双倍计）
- **兼容历史**：分摊在查询时按每条记录的完整起止时间进行，历史库中旧版未拆的长段、watts=0 的旧迁移行无需改写即正确归属；新结的段则在落库时就拆好

## 能耗定额与超标预警模型

- `energy_quotas`：定额配置（scope=room/device × period=daily/weekly/monthly + limit_kwh）。同一对象同一周期唯一；设备定额按 device_id 稳定归属，设备删除后额度保留并标记，历史告警不丢
- `quota_alerts`：告警实例，身份唯一键 `UNIQUE(quota_id, period, period_start)`（含周期粒度，换周期后旧周期告警结存、新周期另立，互不串用旧阈值）；80% 为 warn、100% 升级为 error；状态机 `open → handling → resolved / ignored`（只能逐级流转、可退回、可重开），处理备注与 handled_at 保留；`auto_closed=1` 表示系统自动解除（调额回落/停用/删除/结转），同周期再次越线自动重开并按新阈值通知，人工处理后归零不再被系统复活
- `quota_adjustments`：额度新建/调整/启停/删除留痕（旧值→新值、周期变化、原因），冗余对象快照（scope/target_name，额度删除后历史留痕仍可归属），支持按额度查看与全局查看
- **批量策略模型**：`POST /api/quota/batch`（create/update/enable/disable/delete × 多对象）与 `POST /api/quota-alert/batch-handle`（多告警统一流转）。配置类整批单事务落库、提交后仅 `evaluateAll` 一次（历史告警迁移 + 实时用量重算），避免逐项评估中间态错报；共享参数（周期/额度）非法整批 400，单项冲突逐项标记不拖垮整批，同批内重复对象可被前面已落库项拦截；无变化项跳过不写留痕。系统解除幂等：已 `auto_closed` 的告警不再每节拍重复关闭、重复写时间线
- 用量聚合：「已完成自然日」读 `energy_daily_*` 日固化表（明细只留 7 天，周期比 7 天长也不缺量、告警不被误解除），当前日的已结段按重叠时长分摊，`energy_segments` 未结段实时折算（周期起点之后的当前功率×时长，重启最长补 1h）；跨周期段只计本周期部分，房间按产生用电时的房间快照归并，设备按稳定 device_id 归并；旧库首次启动自动回填日表
- 评估节拍：服务端每 30s 全量评估；设备开关/更新/删除、额度增改后立即评估。校准规则：活动告警的级别/读数/阈值/周期窗口整体同步（上调额度回落安全区自动解除并写时间线，下调额度可降级或升级，用户已闭环且仍越线的只校准读数不复活）；换周期/跨周期旧告警按快照结存（原因区分「调整周期」与「周期结束」）；停用、删除额度自动解除未关闭告警；触发/升级/重开写日志时间线作为通知（级别下调静默），前端轮询按「id+级别+状态」签名弹 toast，同一身份不重复通知
- 统计联动：健康看板新增「定额执行」卡片且告警中心中的定额告警可点击直达处理；能耗统计页底部展示用量占比最高的定额进度；定额 Tab 角标显示待处理/处理中数量

## 告警工单闭环模型（`server/workorder.js`）

- `work_orders`：工单主表（工单号、来源 `device_offline/device_battery/device_signal/quota_over`、设备/定额告警稳定标识、对象/详情快照、级别、状态、处理人、备注、`source_active` 源告警是否仍存在、各状态时间戳）；**部分唯一索引**保证同一告警身份（来源+设备，或来源+定额告警）至多一张未完成工单
- `work_order_events`：工单事件流（系统生成/分派/改派/接单/开始/挂起/继续/完成/复开/源消除/源恢复，含起止状态、操作人+角色、说明），工单详情完整展示
- 同步口径（30s 节拍 + `/api/state` 拉取前补一次）：设备告警与看板告警中心同口径（离线 > 低电量40% > 信号弱60，一台设备一条），定额仅取未闭环的 **error 超标**（80% 预警不开单）；一台设备只要还有任意来源的未完成工单，新出现的告警类型不另开单。源消除 → `source_active=0` + 时间线通知（不自动关单），源恢复 → 自动重新挂源；已完成单在源消除标记后复发才另开新单，源未消除时只能走「复开」
- 状态机：`open→dispatched→accepted→processing⇄suspended→completed→reopened→dispatched…`，服务端逐条校验非法跳转；分派/改派需 `workorder_dispatch`（户主/管理员），接单/开始/挂起/继续/完成需 `workorder_handle` 且**强制处理人本人**（户主也不能代接单），复开放开给任意有处理权限的成员；挂起原因、完成结果、复开原因必填；复开清空上一轮完成/挂起时间，重新分派后时间线开第二轮
- 工单全程写家庭日志（category=`workorder`，带操作人+角色）；设备删除（标识保留、标「设备已删除」）、处理人成员撤销（标「成员已撤销」、可改派）均不影响历史审计

## 家庭共享与权限模型

- `household_members`：成员/访客名册（name 唯一、role、自定义 perms JSON、**scope JSON `{room_ids,device_ids}` 操作范围（空=全屋不限）**、status=active/revoked、访问令牌 token、邀请人、加入/撤销时间与原因）
- `household_invites`：邀请实例（8 位邀请码唯一、角色与授权/范围快照、status=pending/accepted/canceled/expired、7 天过期、接受后关联 member）
- 角色矩阵：户主 owner=全部权限且不可撤销；管理员 admin=全部协作权限但只能管理成员/访客（层级校验，不能邀请/撤销管理员或户主）；成员 member=设备控制 + 场景执行 + 定额告警处理 + 告警工单处理（默认无分派权）；访客 guest=默认仅场景执行。自定义权限与角色默认取**并集**，编辑后即时生效（同一令牌下一次请求即按新授权拦截）
- 身份：演示无登录体系，前端在「家庭共享」页选择在组成员（令牌持久化 localStorage）或凭邀请码加入；所有写请求带 `X-Home-Token`，无令牌=只读浏览（写操作 401），权限不足 403；撤销即令牌置空失效
- 可回收闭环：`邀请 pending → 接受 active（签发令牌）→ 协作（操作全部带操作人入家庭日志）→ 撤销 revoked（令牌失效、授权收回）→ 恢复（重签令牌）/ 重新邀请（新码，接受时复用原身份）`；首次启动预置户主、不同角色成员、一条已撤销访客、一条待接受邀请（示例码 `GUEST2026`）与一条已取消邀请
- 授权贯穿：设备增删改/开关（device_control）、场景触发（scene_execute）与编排（scene_manage）、定额告警状态流转（quota_alert_handle）、定额配置增删改（quota_manage）、告警工单分派（workorder_dispatch）与接单/处理/复开（workorder_handle）、邀请与成员管理（member_manage）全部经同一套权限守卫；**功能权限通过后统一再过资源范围**（设备按当前 `room_id`/稳定 `device_id`，房间/设备定额按其对象，工单按源设备/源定额解析），前端按钮按权限+`in_scope` 双重置灰，服务端为最终裁决；越权拦截 403 并写家庭日志审计
- 范围生效与迁移：编辑范围/接受邀请/撤销恢复后同一令牌下一次请求即按新范围拦截；**房间授权随设备换房动态迁移**（设备换到新房间即离开原房间授权人范围、进入新房间授权人范围），**设备授权绑定稳定 device_id，换房/改名不丢失**；场景可执行性、定额/工单可操作性全部查询时现算，换房后无需任何授权数据改写。户主/管理员始终全屋不限（为管理员携带的范围保存时自动清空）；批量定额/批量告警处理在落库/流转前整批预检，含任一越范围对象则整批拒绝
- 家庭日志：协作事件（邀请/接受/取消/续期/编辑权限/范围调整/撤销/恢复/重邀/过期）、成员执行的设备、场景、告警处理操作与**越权操作拦截**统一写入 `device_logs`，携带 operator/operator_role/category（device/scene/quota/workorder/member），`GET /api/logs?category=&operator=` 过滤
